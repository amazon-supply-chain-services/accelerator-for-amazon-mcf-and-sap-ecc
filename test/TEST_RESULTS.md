## Assertion approach

- **Full-fixture comparison** (tests 1, 4, 7): the complete produced document is
  compared to a saved fixture under `expected/`. For outputs that embed a runtime
  date/time (shipment picking/Goods-Issue dates), those fields are masked to
  placeholder tokens (`#DATE#`) before comparison; the fixtures use the same
  tokens, so the check is stable across runs.
- **Inline field / structure / exception assertions** (tests 2, 3, 5, 6, 8, 9, 10–14): used
  to verify specific extracted fields (carrier/tracking, `AmazonShipmentId`, delivery
  doc), request structure (Sync All search filters, per-delivery GETLIST), or
  specific behaviors (rejection of partial/processing shipment, partial/already-shipped
  cancel, Sync All idempotency skip).

Every meaningful transformation output now has a corresponding `expected/` fixture:
`expected_createOrder.json`, `expected_cancel_ws_delivery_update.xml`,
`expected_shipment_picking.xml`, and `expected_shipment_goods_issue.xml`.
